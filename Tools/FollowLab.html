Putting a setting into the game

Three ways in, cheapest first. All three write the same property names you tuned above.

1 · Console commands works everywhere

Paste into the game console (~) while it runs, or into the editor console. Takes effect on the next tick, no restart.


    

      
      
      
    

  


  
2 · Push live from this page editor or build

  
Unreal ships a web server for exactly this. The Remote Control API plugin, now
    enabled in the project, answers on port 30010 and replies with
    Access-Control-Allow-Origin: *, so a browser may call it. Each value goes as one
    PUT /remote/object/call of SetOverride on
    Default__ViperCompanionTuning, which resolves the parameter name by reflection against
    the follow task. On by default in the editor; a packaged build needs the plugin packaged and
    -RCWebControlEnable on the command line.

One caveat, and it is the browser's, not Unreal's: a page served
      over https may refuse to call http://localhost. If the push fails while the
      game is plainly running, open this page from a local file instead — the same file is saved in the
      project under Tools/ — and it will go through.

  


  
3 · Project Settings editor

  
The same values live under Project Settings → Viper → Companion Tuning,
    where they can be edited with the game running in the editor and saved into
    Config/DefaultGame.ini so they survive a restart.


  
Replaying a real run

  
Drop in a log from a scripted session (the ones with Viper.Companion.Csv 1
    switched on) and the leader stops being a simulation: it walks exactly where it walked in the engine,
    the companion from that run is drawn behind as a ghost, and the companion in front is what these
    settings would have done instead. That is the honest comparison.
